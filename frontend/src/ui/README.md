# Alice UI

The component library for Alice. **Browse it at `/library`**: every component has live examples (resizable, with a text-size control), the code, an API table read from the TypeScript, accessibility notes, and the source. The design language it implements is in [`../../DESIGN.md`](../../DESIGN.md).

```ts
import { Button, Switch, DeviceTile } from "@/ui";
```

## How it is organised

| Where | What |
|---|---|
| `src/ui/*.tsx` + `*.css` | The components, one file and one stylesheet each. Import everything from `@/ui`. |
| `src/ui/type.css`, `layout.css`, `tiers.css`, `glass.css` | Text styles, wrapping layout pieces, what restacks at large text, and the glass material. |
| `src/app/globals.css` | The design tokens (colour, radius, motion) and the app's screens. |
| `src/library/entries/*.ts` | One documentation page per component (typed `Entry`). |
| `src/library/examples/<slug>/*.tsx` | The runnable examples; the page shows each file's source. |
| `src/library/generated/*`, `public/r/*` | Generated by `scripts/build-library.mjs`: API tables, the page list, and the registry. Commit them. |

Components are **owned code, not a package**: copy a file and change it. The registry at `/r/registry.json` publishes the same files in the shadcn registry format (each item lists its files and what it depends on).

## The component contract

1. **The root element** takes `className` (merged with `cn`), passes the rest of its native props through (`ComponentProps<"button">` and so on) and forwards `ref` (a plain prop in React 19).
2. **Every part has a `data-slot`**; state is on `data-*` or `aria-*`, so a part can be styled or tested without a class name.
3. **Variants use `cva`** and the recipe is exported (`buttonVariants`), so a link can wear a button's look.
4. **Values are controlled**: `value` and `onChange(next)` receive the new value, not an event.
5. **A name is required where there is no text**: `IconButton` and `StepButton` need a typed `aria-label`; sliders and switches need `label`.
6. **Every prop has a doc comment.** It becomes the API table, and the generator fails if one is missing.
7. **No app state.** Nothing here imports from `@/lib`. App-specific wrappers live in `src/components`.
8. **Tokens only.** No hex values, no new easing curves. Text sizes are `rem`; text boxes use `min-height`.

## Adding or changing a component

1. Write `src/ui/<name>.tsx` and `<name>.css` (import the css in `styles.css`); export it from `index.ts`. Follow the contract above and document the component and every prop.
2. Add a page: `src/library/entries/<slug>.ts` and one file per example in `src/library/examples/<slug>/` (each starts with `"use client"`).
3. Run `node scripts/build-library.mjs`. It extracts the props, writes the generated files and the registry, and lists anything missing: an undocumented export, an example with no entry, a missing doc comment.
4. Look at the page at each width and text size.

## Checks

| Command | Checks |
|---|---|
| `node scripts/build-library.mjs --check` | Every export documented, every example listed, generated files current (CI). |
| `npm run lint:css` | `rem` for text, no stray fixed heights or `nowrap` (CI). |
| `npx playwright test e2e/library.spec.ts` | Every page and example renders without errors, passes an axe accessibility scan (WCAG 2.x A and AA) in light and dark, fits at 390 px and at 200% text; the registry serves; the controls work. |
| `npx playwright test e2e/alice.spec.ts` | The app, including every screen at four text sizes. |

## Notes that apply across components

- **Text size.** Text follows the person's setting and layouts adapt by tier: `type.css` has the text styles, `layout.css` the wrapping pieces, and `tiers.css` what restacks at large sizes (its rules are written `:root[data-text=...] .x` so they win over screen rules). See `DESIGN.md`, "Text scales".
- **Motion.** One family of curves in `:root` of `globals.css`: `--ease-ios` (sheets), `--ease-out`, `--ease-in`, `--spring`, and the durations `--t-press`, `--t-release`, `--t-ui`, `--t-sheet`. Press feedback is fast in and a soft spring out. `prefers-reduced-motion` removes movement and keeps short fades.
- **Overlays** are built on Base UI (`Modal`, `BottomSheet`): they trap focus, return it on close, close on Escape and on a tap outside, and animate out as well as in. `BottomSheet` dismisses by drag; put `data-base-ui-swipe-ignore` on any child with its own drag.
- **Material.** Floating surfaces (tab bar, sheets, popovers, toasts) use the glass tokens in `glass.css`; it falls back to solid for Reduce Transparency and Increase Contrast.
- **CSS order.** `styles.css` loads before `globals.css`, so a screen rule of equal specificity can beat a component rule. Repeat a parent class to raise specificity, as `tiers.css` and `glass.css` do with `:root`.
- **Tile accordion.** `Tile` becomes a phone accordion when wrapped in `AccordionContext.Provider`; you own the open state.
- **`Html`** is for trusted in-app strings only.
